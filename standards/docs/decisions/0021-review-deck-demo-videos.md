# 0021. Narrated demo videos in the review decks, recorded from a script

- Status: Proposed
- Decided by: Jim (on merging the pull request that adds this record)
- Date: 2026-11-28
- Asked by: Jim

## Context

Jim, 2026-11-28: "A part of the executive review slide deck should include
demos of the most important features of the product. Somehow figure out
how to make videos with voiceovers and close captions to show live demos of
the app working."

The weekly deep review ([`deep-project-review`](../../../.agents/skills/deep-project-review/SKILL.md))
already walks each web app with Playwright and puts screenshots in a Marp
deck, which the `Review decks` workflow builds to HTML and PDF. A video has
to be made the same way: by an agent, from files in the repo, again whenever
the app changes, at no cost (AGENTS.md: free tiers only, fewest vendors, no
local clone).

## Decision

A demo is a JSON script next to the deck (`docs/reviews/<folder>/demos/<name>.json`):
the live app's URL and a list of steps, each a line to say and the clicks,
typing or scrolling to do while it is said. The recorder in
[`docs/reviews/demo-recorder`](../../../docs/reviews/demo-recorder/README.md):

1. speaks each line with **Kokoro**, an open-weight text-to-speech model run
   locally on the CPU;
2. records the live app with **Playwright's video recording**, holding each
   step for as long as its line lasts;
3. writes the **captions from the script itself**, timed from the audio, as
   WebVTT and as a soft caption track in the MP4 (closed captions: the
   viewer turns them on and off);
4. joins it all with **ffmpeg** into a small H.264 MP4 and a poster image.

The `Review decks` workflow records the demos of the decks a pull request
changes and ships the videos in its `review-decks` artifact beside the
deck's HTML and PDF. Videos are build output and are not committed, like
the HTML and PDF. The deck shows each one in an HTML `<video>` on a slide;
the PDF shows its poster.

The review skill gains a "Feature demos" section: two or three narrated
demos of the journeys that matter most to the project's users.

## Options considered

### The voice

| Option | Money | Quality | Fit |
| --- | --- | --- | --- |
| **Kokoro (kokoro-onnx), local** (chosen) | $0 | Natural, close to the paid services | Apache 2.0 model, MIT code. Same words give the same audio, so re-recording doesn't move the timing. 120 MB of model files from a GitHub release, which both the sandboxes and Actions can reach. Adds Python, for this one script only. |
| Piper, local | $0 | Good | MIT, but the project was archived in 2025 and its successor is GPL-3.0. Voices are on Hugging Face, which our cloud sandboxes can't reach. |
| eSpeak NG or Flite, local | $0 | Robotic | Flite is built into the ffmpeg Ubuntu ships, so it needs nothing else. Kept as the fallback (`DEMO_TTS=flite`). |
| Cloudflare Workers AI text-to-speech | $0 inside the daily free allocation | Good | An approved vendor, but it needs an API token: a new secret minted by Infra Mint and Jim's credential approval, and the model can change under us. Worth it only if the local voice falls short. |
| ElevenLabs, OpenAI, Google, Azure or Amazon voices | Free tiers then per character; ElevenLabs paid plans from about $5 a month | Very good | A new vendor, an account and a secret each, and a bill if a free tier runs out. Ruled out by the free-tiers rule. |

### The video

| Option | Money | Why not |
| --- | --- | --- |
| **Playwright `recordVideo`** (chosen) | $0 | |
| ffmpeg screen capture under Xvfb | $0 | More setup for the same picture; Playwright already drives the app. |
| Hosted demo tools (Loom, Arcade, Supademo) | Paid beyond small free tiers | Made by hand, new vendors, and they can't be regenerated by an agent. |

### The captions

| Option | Why |
| --- | --- |
| **From the script** (chosen) | The words are exactly what was said, so there is nothing to mishear, and no model to run. |
| Speech recognition (Whisper) | Another model to download and run, to recover text we already have. |
| Burned into the picture | Always on, so not closed captions, and can't be fixed without re-encoding. |

### Where the videos live

| Option | Money | Trade-off |
| --- | --- | --- |
| **The `review-decks` artifact** (chosen) | $0 on a public repo | Kept 90 days, like the deck's HTML and PDF. The script stays in git, so a demo can be recorded again, though it then shows the app as it is that day. |
| Committed to git | $0 | About 1 MB a demo, in the history forever. Against "no committed build artifacts". |
| A GitHub release per review | $0 | Kept for good; a later step if Jim wants older demos to last past 90 days. |

## Cost

- Money: $0. Every part runs on the GitHub-hosted runner; the repo is
  public, so Actions minutes and artifact storage are free
  ([free-tiers.md](../free-tiers.md)). If the repo went private, a demo is
  about 1 MB of the 500 MB artifact quota and about four runner minutes.
- Free-tier limits: none come near; the model files download from GitHub
  each run (no cache used).
- Claude Code: this pull request once; then writing two or three demo
  scripts adds a few minutes to each weekly review.

## Consequences

- Reviews show the product working, with a voice and captions, not only
  screenshots.
- Kokoro and Python (for the narration script only) join the tech radar in
  Trial.
- A demo that no longer matches the app (a renamed button) fails the
  `Review decks` run on the review PR, which is when someone is looking.
- Demos record production, so they must not change data: read-only
  journeys, or a preview deploy through `DEMO_BASE_URL`. They send the
  `jimhillr-demos` user agent and the `x-jimhillr-synthetic` header so
  analytics can drop them.
